### Phase 1 — `bevy_kana`: `Keystroke`, `Modifiers`, and the chord parser · status: done (`523c3471`)

#### As-built

`"cmd-shift-p"` parses to a canonical `Keystroke { modifiers: Modifiers, key: KeyCode }` and renders back to a canonical string. `Modifiers` is a `bitflags` set over `{control, alt, shift, platform}`, not four `bool` fields — `Keystroke` is the key of Phase 2's prefix index, so `Eq` is a single compare and `Hash` a single write. Canonicalization is a masking step at construction: the `PLATFORM` flag is set only on macOS and a platform token folds into `CONTROL` elsewhere, so `platform-p == ctrl-p` off macOS and `!=` on it hold by construction, with no comparison special case anywhere. The `bitflags` raw constructors stay private, so uncanonical values are unconstructible from outside. Accepted modifier spellings: `cmd`/`super`/`win`/`platform`, `ctrl`/`control`, `alt`/`opt`/`option`, `shift`; source order is irrelevant, `Display` order is fixed, left/right spellings collapse. One `CANONICAL_KEY_MAPPINGS` table backs parsing, `Display`, and the round-trip test, so a later key addition cannot drift between them. `pub const fn Keystroke::new(Modifiers, KeyCode)` builds a keystroke directly from a live `KeyCode` plus held modifiers — it takes already-canonical `Modifiers`, so it cannot introduce an uncanonical value, and it keeps the match path off a format-then-reparse round trip. `KeystrokeSequence` is an ordered, non-empty sequence with the invariant enforced by construction (private field, fallible constructor), parsed from a space-separated string, with `first()`/`len()`/`iter()` and an infallible `first()` because the workspace denies `unwrap_used`/`expect_used`/`unreachable`. `KeystrokeParseError` carries the offending token and its byte offset within the input string. Test cases are written from observed Zed behavior only; Zed's own tests are copyrightable.

### Phase 2 — `bevy_kana`: `SequenceMatcher<T>` · status: done (`27b33a1f`)

#### As-built

`SequenceMatcher<T>` is a prefix-indexed matcher that consumes *completed canonical `Keystroke` values*, never raw key edges, and yields opaque `T` indices. It takes its timeout as a per-call input parameter rather than owning a policy value, and `keystroke/` stays domain-free — no JSON, commands, conditions, tombstones, or `World`. The input boundary is fixed so simultaneous chords (`"j+k"`) stay additive: they would arrive as a preprocessing stage beside it, leaving `sequence.rs` and the prefix/timeout behavior untouched.

The index is a flat `Vec<PrefixNode<T>>` addressed by a newtype index rather than boxed nodes, so the whole trie is one allocation-run at construction and the match path is a `HashMap` lookup plus two `Option` writes. Construction is the only place that allocates or scans. Timing behavior: `g` defers when `g g` is live and fires on timeout; `g` fires immediately when no longer sequence exists; a non-matching next stroke fires the deferred command *and* reprocesses the unmatched stroke once from the root, so two physical strokes can invoke two commands; `cancel_pending()` discards without firing.

`Modifiers::from_pressed(&ButtonInput<KeyCode>) -> Modifiers` in `keystroke/mod.rs` converts held keys into canonical modifiers, applying the platform rule internally: alt and shift map on both platforms; on macOS `SuperLeft`/`SuperRight` → `PLATFORM` and `ControlLeft`/`ControlRight` → `CONTROL`; elsewhere Control maps to the platform modifier (canonicalizing to `CONTROL`) and **physical Super contributes nothing** — it is not a keyboard modifier in this model. It lives in `bevy_kana` because this is the only crate that can see `PlatformShortcutMode`; reimplementing the rule elsewhere would fork the canonicalization.

`KeystrokeSequence` gained `first()`, `len()`, and `iter()`. `first()` is infallible and returns `Keystroke` by value, justified by the non-empty invariant, because the workspace's `unwrap_used`/`expect_used`/`unreachable` denies make a `None` arm unhandleable.

- `crates/bevy_kana/src/allocation_test_support.rs` — `#[cfg(test)]`-only counting `#[global_allocator]`; both the `mod` and the `TEST_ALLOCATOR` re-export are `#[cfg(test)] pub(crate)`, invisible outside the crate

**Binds later work:**

- `MatchOutcome::Reprocess { deferred: Option<T>, keystroke }` at `sequence_matcher.rs:32-37`, exported from `lib.rs:71` and the prelude. It is a struct variant, matched by field name. `None` = no completed prefix to fire before reprocessing this keystroke. Consumers fire `deferred` only when `Some`, then re-call `match_keystroke` exactly once with the same stroke; `Deferred(T)` must **not** dispatch.
- `SequenceMatcher<T>` carries a `T: Copy` bound on the struct — the deferred value is both returned in `MatchOutcome` and stored in `PendingSequence` in one call. Every later phase must pass a `Copy` type as `T`; the command-handle index derives `Clone, Copy, Debug, Eq, PartialEq`.

### Phase 4a — `bevy_kana` `event!` extension, `KeymapCommand` trait, `command!` macro · status: done (`fd7e91e1`)

#### As-built

One `command!` invocation declares an input action, a semantic event, an id, authored palette text, and a capability, and the metadata is readable from the type registry. The registry holds semantic command *events*, not input actions: `"camera::home"` resolves to the `event!` type (`CameraHomeEvent`), not the `action!` marker, and `ReflectEvent::trigger` fires it by name at runtime — the same mechanism BRP uses.

`event!` (`crates/bevy_kana/src/input/event.rs:25`) is the type `command!` wraps and adds `#[reflect(KeymapCommand)]` to. It gained optional `reflect:` arms (unit and payload forms) that splice extra entries into the `#[reflect(...)]` list it writes itself:

```rust
($(#[$meta:meta])* $event:ident, reflect: $($extra:ident),+ $(,)?) => {
    $(#[$meta])*
    #[derive(Event, Reflect, Default)]
    #[reflect(Event, $($extra),+)]
    pub struct $event;
};
```

The `reflect:` arms come first — a `reflect:` invocation must not fall through to a non-`reflect` arm — and the two original arms are byte-identical. This is not a forwarded attribute: `event!` matches `$(#[$meta:meta])*` before it writes the derive, so a forwarded `#[reflect(KeymapCommand)]` would land ahead of the derive that defines the `reflect` helper, which is the `legacy_derive_helpers` future-incompatibility warning and fatal under `-D warnings`. No dependency cycle and no manifest change: `$extra:ident` captures a bare token that resolves at the call site, and `bevy_kana` never names `KeymapCommand`.

`command/reflect_command.rs` holds the `KeymapCommand` trait and the hand-written `ReflectKeymapCommand` type data, populated from the trait's associated consts (`ID`, `TITLE`, `DESCRIPTION`, `CAPABILITY`) through a blanket `impl<T: KeymapCommand> FromType<T>`. The trait is named `KeymapCommand`, not `Command` — `Command` is in `bevy::prelude`, so a local one is an E0659 ambiguity in any file globbing that prelude.

`command!` lives in `hana_rubric`, not `bevy_kana`, because declared ids and `CommandId` are the keymap file's vocabulary. Its expansion reaches the wrapped macros through `$crate::action!` / `$crate::event!`, backed by `#[doc(hidden)] pub use bevy_kana::{action, event};` in `lib.rs` — `#[macro_export]` puts them at `bevy_kana`'s crate root, and `doc(hidden)` does not affect name resolution. The macro names both the action and the event identifier because stable `macro_rules!` cannot derive one from the other. `id` is const-validated at expansion via `const _: () = assert!($crate::CommandId::is_valid($id));`, which passes the workspace `clippy::panic` deny. Generated command types stay `pub`.

`command/capability.rs` holds `Capability` — a payload-free `Clone, Copy, Debug, Eq, PartialEq, Reflect` enum, const-constructible and usable as an associated const:
- `OneShot` — binds to any `KeystrokeSequence`.
- `Held` — binds to any single keystroke including modifiers (`f`, `shift-f`, `cmd-shift-f`), never a multi-key sequence. This is a property of the command carried by the registry, not a format limitation.
- `Unremappable` — reachable only through the app's permanently-registered bindings, never nameable in a keymap file. The library never learns what an input context is.

`diagnostic.rs` gained `pub message: String` — required like every other field, empty string where none applies, distinct from `suggestions` (machine-applicable replacement text) — plus the registry-validation variants `DuplicateCommandId`, `MissingCommandTitle`, `MissingCommandDescription`. `title` is the palette row and fuzzy-search target; `description` is the palette's secondary line and the schema's hover text; both required even for `Held`, which has no palette row but still needs the key-binding editor's label.

### Phase 4b — `hana_rubric`: `CommandRegistry`, startup validation, cached invocation · status: done (`3c5db62b`)

#### As-built

`command/registry.rs` holds `CommandRegistry` — the validated id → registration table a palette reads — plus `CommandEntry` (title, description, cached `ReflectEvent` handle, `Invocation`) and construction/validation/lookup. It is built once by scanning the type registry for `ReflectKeymapCommand` type data; there is no generic `T` at scan time, so each entry's `CommandId` comes from `CommandId::try_from(entry.id)` on the `&'static str` the type data carries. The `ReflectEvent` handle is cached at build time for **every** capability, so no reflection lookup sits on the input path. `#[reflect(KeymapCommand)]` is discovered automatically because `reflect_auto_register` is on for this workspace's `bevy` — automatic registration never covers generic instantiations, so a generic command type needs an explicit `register_type`.

`Invocation` is the resolved counterpart of the declared `Capability`, living on `CommandEntry`:

```rust
pub enum Invocation {
    OneShot,
    Held(CustomInput),
    Unremappable,
}
```

Converting `Capability` into `Invocation` is the one place a `CustomInput` is allocated (one per `Held` command, in a single construction pass with `&mut World` / `ResMut<CustomInputs>`), and a `Held` command with no input is unrepresentable — not `Option<CustomInput>` plus a documented invariant. `CommandRegistry` exposes a `CommandId` → `CustomInput` lookup.

Validation rejects duplicate declared ids (`DuplicateCommandId`), an empty title (`MissingCommandTitle`), and an empty description (`MissingCommandDescription`) — the consts are always present, so emptiness is the only checkable failure — plus two cases reachable only by hand-written `KeymapCommand` impls that bypass `command!`: `InvalidCommandId` (when `CommandId::try_from` fails) and `CommandEventNotReflected` (when a type carrying `ReflectKeymapCommand` has no `ReflectEvent`). Each `message` names the offending id or type path. These are diagnostics, not panics, because an outside crate can trip them.

A `Held` command fires a two-phase semantic event: `command!`'s held form generates `pub struct $Event { pub phase: HoldPhase }` with `HoldPhase` = `Begin`/`End`, because BRP, scripts, and tests cannot hold a key down. Both input paths converge on the same `CustomInput` before anything downstream sees them — the matcher writes the input's `ActionValue`, and the `Begin`/`End` observer (registered by the same construction path that allocates the inputs, since that is the only place holding the map) writes the same input's value. Writing `End` when already released is a no-op. `HoldPhase` lives in `command/capability.rs` beside `Capability` with `Clone, Copy, Debug, Default, Eq, PartialEq, Reflect` and `#[default] Begin`, reflected and registered so BRP can construct the payload.

`KeymapCommand` gained an `Event` supertrait and a required `hold_phase(&self) -> Option<HoldPhase>` with no default body — a hand-written held command that forgets it fails to compile rather than registering as silently inert — and `ReflectKeymapCommand` gained `pub(crate) register_held_observer: fn(&mut World, CustomInput)`, because a typed `On<Event>` observer cannot be built from the type data alone.

Visibility: `pub` for the read-only query/invoke façade; `pub(crate)` for `CommandEntry`, its reflection handle, and mutable construction.

### Phase 6 — `hana_rubric`: JSONC document model with retained source spans · status: done (1cfad3fa)

#### As-built

A keymap file parses into typed stages that remember where every binding came from. The document root is an **object** (`$schema` member plus an ordered `"bindings"` array of blocks) — an array has no members, so an editor could not learn which schema applies. Each block has an optional `"context"` and a `"bindings"` map; block order is preserved and later blocks override earlier ones. Parsing uses `serde_json_lenient`, so comments and trailing commas are accepted. A binding value is a command id string or `null` (`BindingEdit::Unbind`, the tombstone); the `[id, args]` array form is specified in the type but rejected with an arguments-not-supported diagnostic, keeping argument support additive.

Two parsers run over the same text: `serde_json_lenient` decodes into private wire structs, and a hand-written `JsoncScanner` records per-key byte ranges and 1-based line/column into a `SourceIndex`. A custom `Deserialize` for `WireBindings` (repeated `next_entry()` into `Vec<(String, Value)>`) preserves duplicate keys and source order, which keeps the two passes in step. Explicit length checks precede both `zip` pairings (`parse_blocks`, `parse_bindings`) and raise a whole-file diagnostic on mismatch rather than attaching later errors to the wrong key.

`KeymapDocument::parse` returns `Result<(Self, Vec<Diagnostic>), Vec<Diagnostic>>`. `Err` is a whole-file failure (serde decode failure, source-index failure, block/binding count mismatch); `Ok` carries every valid binding **plus** every per-binding diagnostic, so a caller that ignores the success-path diagnostics drops them silently. Per-binding failures are skipped from `blocks`; duplicate keys within one block are retained in source order so last-wins is applied at merge time, not parse time.

`ContextExpr` holds only `Name(ConditionName)` in v1 — a bare name parses identically under a future boolean grammar, so `&&`/`||`/`!` composition stays additive; the type's doc comment says not to flatten it to a `ConditionName`. `ConditionName::new(impl Into<String>)` is `pub(crate)` in `condition.rs`, added here as its first caller's phase.

### Phase 7 — `hana_rubric`: layering, tombstone resolution, compiled per-context matchers · status: done (a95983bb)

#### As-built

Embedded defaults plus user edits resolve to one `CompiledKeymap` holding a `SequenceMatcher<CommandHandle>` per context, with tombstones applied before compilation. `CompiledKeymap` is **replaced wholesale on reload, never edited in place** — it is not read-only: every matcher method (`match_keystroke`, `resolve_timeout`, `cancel_pending`) takes `&mut self`, so routing takes `ResMut<CompiledKeymap>`, never `Res`. `MergedKeymap::from_sources` / `from_documents` take `protected_keystrokes` and are pure with respect to `World` mutation — both take the registries by shared reference and `from_merged` clones every `CommandEntry`.

The merge algorithm, as shipped:

1. Embedded defaults first, then the user file; within each source, blocks in file order.
2. Merge identity is `(condition-or-global, complete canonical keystroke sequence)`.
3. At each identity the last **valid** edit wins, as `Bind(handle)` or `Tombstone`. An invalid edit is skipped and leaves the prior valid entry in place — a bad user line can never erase a working default. An explicit tombstone still overrides regardless of direction.
4. For active context `C` and sequence `S`, `(C, S)` wins **including when it is a tombstone**; only genuine absence falls through to `(global, S)`. A tombstone dispatches nothing and suppresses the global fallback. Three distinct states at an identity: absent inherits the global, a command replaces it, `null` makes the key inert. To get global behavior inside a context, bind that command there explicitly.
5. Tombstones apply to complete sequences, never prefix subtrees: a tombstone on `g` does not remove `g g`; a tombstone on `g g` lets `g` fire immediately.
6. One resolved matcher compiles per context **after** tombstones and global fallback, so only live sequences contribute prefixes. The global set is pre-merged into each per-condition matcher, so rule 4 costs nothing at dispatch and there is no fallback chain to walk. Cost is `O(contexts × bindings)` of setup memory and reload work; it removes context scans, string comparison, reflection, and allocation from the input path — the compiled per-context matchers are what underlie the input-path budget invariant.
7. **No cross-source duplicate check** — repeating a context across sources *is* the override mechanism. A conflict entirely within one source, by contrast, rejects every participant; that is deliberate.

`CompiledKeymap` carries a `Generation`, a `global: SequenceMatcher<CommandHandle>` field alongside the per-condition map (an app registering zero conditions, and every frame before context sync first runs, otherwise has no matcher at all), and a table of resolved `CommandEntry` values built in `CommandRegistry::iter_entries()` id-sorted order so it is reproducible. `CommandHandle` is the matcher's `T` — an opaque index deriving `Clone, Copy, Debug, Eq, PartialEq`. No name survives into the compiled form; dispatch goes through `CompiledKeymap::invocation(CommandHandle) -> Option<Invocation>`, never through `CommandRegistry` by id.

Semantic resolution happens here and fills `Diagnostic::suggestions`: an unknown command id names the three closest matches via a hand-rolled bounded Levenshtein over `CommandRegistry::iter()`, at diagnostic time only, with no new dependency. An unknown condition name lists the registered names. A block whose `"context"` is present but unresolvable contributes **no edits at all** — not to its intended context, not to global; only an absent `"context"` means global, and `parse_context` returns a source location for an explicit `"context": null` so that arm is reachable. A `Held`-capability command bound to a multi-key sequence, an `Unremappable` command named anywhere, and any sequence whose **first canonical stroke** is a protected keystroke are per-binding rejections; the protected check compares parsed, platform-normalized keystrokes so `super-p`, `win-p`, and modifier-order spellings cannot slip through. The protected list holds exactly one entry, arriving through `KeymapPlugin`'s `.with_protected_keystroke(Keystroke)` — the library may not depend on hana, so configuration injection is the only route, and `Unremappable` does not cover it (that protects a *command* from rebinding; a user could bind some other command to the chord and shadow it).

`Diagnostic` gained an advisory/failure severity here. An unrecognized block member, a duplicate context name, and a duplicate binding key are **advisory** (the load succeeded); an unknown command id, an unparseable keystroke, and a reserved-keystroke rejection are **failures**. Advisories are logged at warn and retained across a successful load. `WireBlock` keeps no `deny_unknown_fields` — that would reject a whole block and cost its valid bindings — so the scanner records unrecognized member names with spans and `RECOGNIZED_BLOCK_MEMBERS` (`merged.rs:76`) is the load-time authority for the legal list. This phase added the last three `DiagnosticKind` variants: `HeldCommandInSequence`, `UnremappableCommand`, `ReservedKeystroke`.

### Phase 8 — `hana_rubric`: JSON Schema generation · status: done (2b663825)

#### As-built

A JSON Schema is generated in memory at startup from the command registry, the condition registry, and the document model, and returned as bytes — it never touches the filesystem (Phase 9 publishes it). The document is built as a `serde_json_lenient` value and serialized: the content is a runtime enumeration of whichever commands and conditions the application registered, not the shape of a Rust type, so neither reflection nor `schemars` applies and no manifest change was needed.

Emitted shape: the command-name field is an `anyOf` of `{"type": "string", "const": "<id>"}`, each carrying the authored description as `description` (hover text); the `"context"` value is an enum of registered condition names with their `#[strum(message)]` text; the binding value accepts a command-id string or `null`, described as "inert at this identity, not inherited"; a root `"description"` marks the file generated. Only commands where `capability.is_user_bindable()` holds are emitted — offering an `Unremappable` command would autocomplete a guaranteed load error. `Held` commands do appear, with the single-keystroke-only restriction stated in their emitted description.

`"additionalProperties": false` sits on the root object and on each block object, so a schema-aware editor underlines `"contxt"` as it is typed; the load-time advisory covers editors without schema support. The schema keeps its own block-member list and a drift test asserts it equals `RECOGNIZED_BLOCK_MEMBERS` (promoted to a module-level `pub(super)` in `merged.rs`, referenced from `schema.rs` only by the test module). Adding a legal block member requires updating both lists — the drift test fails until both move.

The schema is referenced from the keymap by a relative `"$schema": "./keymap.schema.json"`, so any editor's JSON language server gives identical behavior with no editor-specific setup and no custom LSP request or URI scheme. The app never reads the schema back, so tampering with it yields wrong autocomplete until relaunch and cannot change a binding.

### Phase 10 — `hana_rubric`: the disk worker — watch, debounce, retry, poll · status: done (a182c2a9)

#### As-built

`DiskWorker` owns every filesystem touch — initial read, first-launch stub creation, the parent-directory watch, debounce, retry, the polling audit, confirmed deletion, and companion publication — on its own thread, so editor save patterns, network filesystems, and watcher failures never reach the frame schedule. It **never parses**: it produces byte snapshots plus a source path and hands them across a bounded coalescing slot; parsing, merging, and compiling are pure and happen app-side. `start_disk_worker` takes `&KeymapPaths` so paths are resolved exactly once — resolving them on both threads can disagree and send the worker into the developer's real `~/.config`.

The parent directory is watched **non-recursively** with the canonical filename filtered including rename destinations; watching the file directly loses the watch when an editor replaces the directory entry. Editors save by writing a temp file and renaming over the target, so the watcher sees several events per save and may briefly observe the file as missing: notifications coalesce into one bounded dirty flag with trailing-edge debounce, transient `NotFound` is retried for a bounded grace interval, and only absence persisting past that interval applies the confirmed-deletion policy (deleting the user file removes its overrides and restores embedded defaults). Watcher errors, rescan signals, and channel disconnection are durable health failures: reread completely and recreate the watch, recording the failure in the diagnostic resource rather than only logging it. A slow polling audit runs alongside native events rather than waiting for an error — `notify` documents that NFS may emit no events at all without reporting watcher failure.

The message crossing the slot is **tri-state**; the third state, `snapshot: Some(contents: None)`, is the confirmed-deletion policy crossing the worker/app boundary. `take_message` may append one synthesized diagnostic reading "N older disk diagnostics were discarded before delivery." — it has no source span and no originating binding, so any consumer of the diagnostic list must tolerate that. `DiskWorkerMessage`'s field is `pub(super)`, so it is unconstructible outside `disk::worker`; the app-side commit therefore takes `(Option<DiskSnapshot>, Vec<Diagnostic>)`. `DiskWorkerChannels` is wrapped in a newtype resource declared in `keymap_plugin.rs` because `disk/` imports no bevy, and that newtype's `Drop` is the shutdown — there is no second shutdown system. `WorkerTimings.poll` is `Option<Duration>` so a test can disable the polling audit and prove a watcher-driven path in isolation.

Embedded defaults load first (they cannot fail), then the config directory is touched; companion publication runs from this worker and its failure does not prevent the watch from starting. The first-launch stub is written **only if absent** and never overwritten, with exactly `{"$schema": "./keymap.schema.json", "bindings": []}` — the schema's root emits `"required": ["bindings"]` and `WireDocument.bindings` has no `#[serde(default)]`, so an empty file or bare `{}` is a whole-file parse failure the app would report against its own stub on every launch. The `$schema` key is what makes editor completions work with no workspace settings; editor assistance therefore begins after the app has run once, stated as the installation contract in the crate docs.

**Files:**
- `crates/hana_rubric/src/disk/worker/{mod.rs, channels.rs, runtime.rs, watch.rs}` — a directory module (the single-file form crossed the workspace split threshold at ~608 non-test lines; no submodule exceeds 378). `mod.rs` is declarations and `pub(crate)` re-exports only. **Every `disk/worker.rs` path cited in this plan reads as `disk/worker/`.**

- `crates/hana_rubric/src/disk/mod.rs` — worker startup and message types only. The worker's channels are `pub(crate)`.

**Binds later work:**
- The worker produces the real-file-path diagnostics.
- No application name ⇒ no disk worker starts and nothing touches the developer's real config directory.
- An item-scoped `#[expect(dead_code, …)]` remains in `disk/worker/runtime.rs`; wiring the worker's entry point fulfils it, and roughly ten more expectations across `disk/` and `keymap/`, in one diff — each a hard error under `-D warnings`, so treat it as a sweep, not a single deletion.

**Gotchas:**
- Bounding a mailbox means bounding its **payload**, not just its slot count. The diagnostics `Vec` inside the capacity-one message grew without limit because each unread publication prepended the previous message's diagnostics.

### Phase 11b — `hana_rubric`: command construction and dispatch · status: done (f5fc90c0)

#### As-built

Command construction lives on the `KeymapCommand` trait: `fn build() -> Self` is required on every impl, and `command!` generates it per arm (`@build unit`, `@build held`) beside the existing `@hold_phase` arms in `command/reflect_command.rs`. Non-held returns `None` from `hold_phase`; the `held,` form returns `Some(self.phase)`, and `@build held` constructs `Self { phase: HoldPhase::Begin }` explicitly. `build` takes no arguments; a payload argument can be added later without touching call sites.

Putting the constructor on the trait is what removes the `T: Default` bound from the blanket `impl<T: KeymapCommand> FromType<T>`, which in turn unblocks a monomorphized dispatch pointer: `ReflectKeymapCommand` carries `dispatch: fn(&mut World)`, filled by `fn dispatch_command<T: KeymapCommand>(world: &mut World) { world.trigger(T::build()); }`. `World::trigger` takes the event by value; a one-shot command is zero-sized and a held command is one `Copy` field, so dispatch allocates nothing and never consults the type registry. Downstream the delivered event is the same semantic event as the `bind_action_system!` route produces and is indistinguishable from it.

`invoke(&self, &CommandId, &mut World) -> Option<()>` — no `&dyn PartialReflect` and no `&TypeRegistry` parameter. `CommandEntry` carries neither a cached prototype nor a `reflect_event` handle. Held commands do not go through dispatch on the input path — Phase 11c writes their `CustomInput` value directly; `build` still exists for them because `register_held_observer` needs it.

**Files:**
- `crates/hana_rubric/src/command/reflect_command.rs` — the `KeymapCommand` trait (`build` beside `hold_phase`, `:15`), `macro_rules! command!` and its build arms, `ReflectKeymapCommand`'s `dispatch` pointer
- `crates/hana_rubric/src/command/registry.rs` — `CommandEntry`, `invoke`
- `crates/hana_rubric/src/command/{action,event}.rs` — unchanged by this phase
- `crates/hana_rubric/src/keymap/{compiled,merged,schema}.rs` — test fixtures, which a required trait method forces to implement `build`

**Binds later work:** the bound generic dispatch actually needs is `for<'a> T::Trigger<'a>: Default` — the event's associated trigger type, the same bound bevy's own `ReflectEvent` impl carries. `ReflectEvent` is now a validation-only requirement with no functional consumer. A remote caller cannot supply an event payload, so invoking a `Held` command by short id always dispatches `HoldPhase::Begin` and its `End` phase is unreachable by that route.

**Gotchas:**
- `ReflectEvent::trigger` is not a pass-through in `bevy_ecs 0.19.0`: it calls `from_reflect_with_fallback` (`bevy_ecs-0.19.0/src/reflect/mod.rs:108`), which does a `ReflectFromReflect` registry lookup and materializes a fresh boxed event on every call. No caching on the caller's side can remove that cost.

The two **unit** arms (`:37`, `:51`) derive `Default`; the two **field** arms (`:43`, `:57`) derive `Event, Reflect` only, so a held event has neither `Default` nor `ReflectDefault`. Anything reaching `from_reflect_with_fallback` on a held event — stock `world.trigger_event`, not `invoke` — can still panic. The hazard is displaced off the short-id `invoke` path, not removed.

### Phase 11c — `hana_rubric`: the per-frame runtime · status: done (a1e010f1)

### Phase 12 — `hana_rubric`: plugin assembly and the reload transaction · status: done (aceb0cdb)

#### As-built

`hana_rubric` is assembled end to end: `Plugin::finish` builds the registries, publishes companion files, starts the disk worker, and commits the first generation; `commit_reload` runs before routing every frame. The plugin root wires all modules and no module reaches upward:

```text
diagnostic          → nothing
command, condition  → diagnostic
disk                → diagnostic
keymap              → command, condition, diagnostic, keystroke
keymap/schema       → command, condition
```

`keymap → disk` is deliberately absent — the plugin root hands generated companion buffers to the worker, receives byte snapshots back, calls the pure keymap compiler, then invokes the runtime transaction.

**Builder surface:** `KeymapPlugin::new()`, `.with_app_name(&str)`, `.with_defaults(&'static str)` (`include_str!`-supplied by the consumer), `.with_protected_keystroke(Keystroke)` — `#[must_use]`, takes `self` by value, pushes onto a `Vec<Keystroke>`, so repeated calls accumulate rather than replace and duplicates are not an error — plus the terminal `for_state_context::<C>()` / `for_context::<C>()`. `KeymapPlugin.app_name: Option<String>` (`keymap_plugin.rs:46`) and a bare-`Option` `defaults` field; the terminal call carries the configuration into `KeymapPluginConfiguration` (`app_name` at `:282`), since the terminal plugin is what gets added to the `App`. Calling both context-source methods is rejected rather than silently double-registering. There are three terminal plugin types — `KeymapPlugin` itself for a global-only app, `ResourceContextPlugin<C>` and `StateContextPlugin<C>` otherwise — so assembly is one shared crate-private routine, `finish_assembly`, guarded so a both-plugins app does not initialize the registry twice, start two disk workers, or commit twice.

`finish_assembly` commits a defaults-only generation **first**, before app name, paths, schema, and worker are touched, so embedded defaults load with no config directory at all and the keymap is live from frame zero; every worker message is then an ordinary reload. It stamps `EMBEDDED_DEFAULTS_SOURCE` on defaults-side diagnostics — `const EMBEDDED_DEFAULTS_SOURCE` at `keymap_plugin.rs:38`, private, exported from neither `lib.rs` nor the prelude; write sites `keymap_plugin.rs:203`, `:330`, `:371`, `:383`, `:399`. `record_unavailable_keymap_paths` writes `app_name.unwrap_or(EMBEDDED_DEFAULTS_SOURCE)` (`:399`); it and `insert_keymap_path_availability` both take `Option<&str>` by inheritance from the fields.

`install_runtime` is the crate's only idempotent scheduling site: it `init_resource`s `KeymapLoadFailures` and `KeymapRuntime` (eager, so a scripted `HoldPhase::Begin` before the first commit cannot write `CustomInputs` through the registry's no-refcount fallback) and schedules `commit_reload` `.before(KeymapSystems::Route)`. `commit_reload` is an exclusive system, `fn commit_reload(world: &mut World)`, taking `(Option<DiskSnapshot>, Vec<Diagnostic>)` — the plugin destructures the worker message at the call site. It is UTF-8 decode → `from_sources` → `compile` → swap the resource; the first commit inserts `CompiledKeymap`, later commits replace it wholesale. `Generation(previous.0 + 1)` is the counter.

**Two-tier failure, keyed on `from_sources`'s `Result` arms and never on `DiagnosticKind`** (both tiers emit `Syntax`): `Err` is the whole-file tier — nothing changes, not the generation, not the pending sequence, not held actions — and `Ok((merged, diagnostics))` is the per-binding tier, committing one complete generation of defaults plus every valid edit and reporting the rest. Invalid UTF-8 is the whole-file tier. The worker's tri-state message carries the deletion policy: `snapshot: None` is diagnostics only with no generation change; `Some(contents: Some(bytes))` runs the transaction; `Some(contents: None)` is a confirmed deletion and commits a defaults-only generation, which is not an error and produces no failure diagnostic.

Registry and condition validation stay **all-or-nothing** — a malformed declaration is code, not user data. `CommandRegistry::initialize`'s `Err` arm records the diagnostics, logs at error level, and inserts an empty registry built by `pub(crate) fn empty()`; every binding then fails to resolve and is reported individually, and the app starts. A `RegistryValidationFailed` resource, inserted only by that arm and by `register_context`'s failure path, is what suppresses strict shipped-default validation; the shipped-default rejection still fires normally when the registry built successfully. **A failed *context* registration leaves input routing disabled entirely, global bindings included** — deliberate, since the context enum is the application's own and the failure surfaces on the first launch after the enum changes; the recovery chord is unavailable in that state and the error-level log naming the offending variant is the only signal.

### Phase 14b — `hana_rubric`: `DerivedContext<C>` — declaring a context from world facts · status: done (`581c7d87`)

#### As-built

A context variant is a Bevy run condition, and the derivation is an ordered table of them rather than a hand-written `if`-chain.

```rust
pub struct DerivedContext<C> {
    fallback: C,
    rules:    Vec<(C, BoxedCondition)>,
}

impl<C: KeymapContext + FreelyMutableState> DerivedContext<C> {
    #[must_use] pub fn new(fallback: C) -> Self;
    #[must_use] pub fn when<M>(self, context: C, condition: impl SystemCondition<M>) -> Self;
}
```

`when` boxes the condition through `IntoSystem::into_system`; the `M` marker generic lets combinator chains infer at the call site. **Declaration order is priority; first match wins** (`derived_context.rs:126`) — no scoring, no specificity rules. The fallback is a constructor argument, not `#[derive(Default)]`, so an unrelated change to the enum's default cannot silently change keymap routing. The bound is `FreelyMutableState`, not `States`: `NextState<C>` and `insert_state` are defined only for it, and `#[derive(States)]` supplies it already.

`KeymapPlugin::for_derived_context(self, derived: DerivedContext<C>) -> impl Plugin` sits beside `for_context` and `for_state_context`. `DerivedContextPlugin<C>` holds the table in `Mutex<Option<DerivedContext<C>>>` — `Plugin::build` receives `&self` and `BoxedCondition` is not `Clone` — and takes it out exactly once during build; evaluation reads a plain `Vec` from a resource and takes no lock. `build` runs `install`, adds `StatesPlugin` when absent (`insert_state` panics without `StateTransition`), calls `register_context::<C>(app, ContextSource::Derived)`, and only inside the `is_ok()` branch runs the three validations, strips fallback-targeting rules, calls `insert_state(fallback)`, `System::initialize`s every remaining boxed condition, inserts the rule table, registers an `On<CheckChangeTicks>` observer forwarding `check_change_tick`, and adds `evaluate_derived_context::<C>` in `PreUpdate` `.before(KeymapSystems::UpdateActiveCondition)` plus `sync_state_condition::<C>` in `UpdateActiveCondition`. A rejected registration leaves no state, table, observer, or system behind. `finish` calls `finish_assembly`.

`evaluate_derived_context<C>(world: &mut World)` is an exclusive system: `resource_scope` the table out, walk in declaration order calling `run_readonly((), &*world)` — `Ok(true)` selects and stops, `Ok(false)` and `Err(RunSystemError::Skipped(_))` continue, `Err(RunSystemError::Failed(error))` goes to the world's fallback error handler with `ErrorContext::RunCondition` and counts as `false`, no match yields the declared fallback. `NextState<C>` is written only on change. Totality is structural — the fallback is unconditional, and there is no "keep the previous variant" mode.

All three context plugins return `is_unique() -> false`, so a repeated registration reaches `register_context` and is diagnosed instead of panicking in `add_plugins`. `for_context`, `for_state_context`, and `for_derived_context` remain mutually exclusive, one per app.

Three startup validations run synchronously inside `build`, all emitting `DiagnosticSeverity::Advisory` through the context-diagnostic retention path and none setting `RegistryValidationFailed`: a non-fallback variant with no rule is unreachable (one advisory); a rule targeting the fallback variant is one advisory **and the rule is removed from the table** (first-match-wins would otherwise let it mask every later rule); the same non-fallback variant targeted twice is one advisory naming the variant, rules left in place.

**Decided (2026-08-03):** make the held-prefix precedence symmetric — raised by the Phase 20 architect review, approved by the user the same day

Actual problem:
Phase 19 made the held-prefix policy source-aware in `crates/hana_rubric/src/keymap/merged.rs`: when a held single-stroke binding conflicts with a longer sequence that shares its prefix, which one survives now depends on which layer each came from. The rule was specified for one direction only, and the mirror direction falls through to the older blanket rule that rejects every participant.

What exists now:
- **Shipped default binds `f` as a hold, user file adds `f g`** → the user's `f g` is rejected, the shipped `f` survives, one diagnostic names both commands and both source files. This is the approved behavior from Phase 16 and it is implemented.

Neither governing principle produces the second outcome. "Later layers win" would keep the user's hold and drop the shipped `f g`. Apply the same precedence in both directions — a valid hold wins over a conflicting longer sequence from the *other* source layer, whichever layer the hold is in. Make it symmetric, in `keymap/merged.rs`. Cost is one added case in the conflict resolver plus its two tests (user hold beats shipped sequence; explicit tombstone still overrides).

- **`keymap::install` accepts an explicitly configured keymap and then ignores it.** `crates/fairy_dust/src/keymap.rs:154-163` returns early on `is_plugin_added::<KeymapPlugin>()` before reading `ChosenKeymap`, so an app that called `.with_command_palette_keymap(X)` *and* added its own `KeymapPlugin` has `X` dropped with no panic, log, or diagnostic. The documented case — an app that installed its own plugin and never configured one — is deliberate and correct; discarding a *recorded* choice is a different case, and it silently produces an application whose configured palette keymap never compiles. Phase 25's scoping decision (hana builds its own palette and takes no `fairy_dust` dependency) removed the consumer that would have hit this first, so it is a latent fairy_dust defect rather than a blocker for any phase.
- **The palette's platform opener discards its failure reason.** `open_path` (`crates/fairy_dust/src/command_palette/mod.rs:351`) returns `()` and only `error!`s, so a failed open or reveal produces a log line and no change in the box. The deferred Phase 23 Work Order specified this boundary as "a `Result` with a named failure type, or an enum stating opened / failed-with-reason. Not `Option<()>` and not `bool`" precisely so the reason survives to user-facing text. Give it a named return and render it in the row that was clicked.
- **The palette does not follow a window resize unless the reader is typing.** Geometry is recomputed only inside `rebuild_palette`, which runs on `ImeTextChanged`, so resizing with the box open and idle leaves it at its old width and origin. It needs a resize-driven rebuild path alongside the text-change one.
